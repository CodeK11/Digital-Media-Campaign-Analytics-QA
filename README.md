# Digital Media Campaign Analytics & QA

**Portfolio case study | Excel + Power BI + Python + SQL + BigQuery**

This project demonstrates a media-analyst workflow: campaign-report intake, quality assurance, standardisation, media KPI calculation, reconciliation, reporting and a separate public-data web-analytics exercise.

## Data integrity and scope

The project deliberately keeps two evidence layers separate:

1. **Simulated agency-style campaign delivery data** (`data/raw/simulated_agency_reports/`, `data/processed/`, and the Excel workbook). These fictional practice records cover 1–31 August 2026. They are not actual Ebiquity data, client data, platform exports or real campaign results. QA issues were intentionally injected.
2. **Google's public GA4 ecommerce sample** (`bigquery-public-data.ga4_obfuscated_sample_ecommerce`). The extracted data covers 1 November 2020–31 January 2021 and is historical, obfuscated web-event data. It is not paid-media delivery data and does not contain the campaign delivery measures in the simulated layer.

Do not combine these sources into a single real-world campaign performance claim. The simulated layer demonstrates paid-media report QA and KPI logic; the GA4 layer demonstrates public-data extraction, aggregation and web analytics.

## Reproducing the campaign-data workflow

1. Open the Excel workbook and inspect `Read Me`, `Raw Intake`, `QA Log`, `Clean Fact`, `KPI Summary`, `Campaign Summary` and `Dashboard`.
2. From the project root, run `python src/clean_validate_media_data.py` (requires pandas and numpy).
3. Use `sql/validation_queries.sql` for SQL checks after loading the accepted fact CSV into the target database.
4. Follow `powerbi/POWER_BI_BUILD_GUIDE.md` to reproduce the Power BI model and report. The native `.pbix` is created and saved locally in Power BI Desktop; it is not generated by this package.

## Reproducing the GA4 exercise

Follow `docs/GA4_BIGQUERY_EXTRACTION_GUIDE.md`. Run the documented SELECT query in BigQuery, export the results as CSV, save it as `data/processed/ga4_web_analytics.csv`, and import it into Power BI as `GA4_Web_Analytics`. The query output is an aggregate table, not raw event-level data.

## Media KPI definitions

- CTR = clicks / impressions
- CPC = media cost / clicks
- CPM = media cost / impressions × 1,000
- Conversion rate = conversions / clicks
- CPA = media cost / conversions
- ROAS = attributed revenue / media cost

Aggregate rates are calculated from summed numerators and denominators, not by averaging daily rates. Compare CPA/ROAS across platforms only after checking attribution windows, conversion definitions, currency and deduplication.

## Power BI report structure

Four analytical pages:
1. Campaign Overview
2. Channel & Campaign Analysis
3. Data Quality & Reconciliation
4. GA4 Web Analytics

Two drill-through detail pages:
5. Campaign Detail
6. QA Investigation

The GA4 page is a separate web-analytics view. The Campaign Detail and QA Investigation pages use campaign drill-through context.

## Known limitations

- Simulated campaign data is not evidence of real campaign outcomes or professional media-buying experience.
- The GA4 sample is obfuscated and historical; it should not be used for current market benchmarking.
- `unique_users` in the extracted GA4 aggregate is a distinct-user count within each grouped row. Summing it across groups can count the same pseudonymous user more than once; label any sum as grouped distinct-user counts, not overall unique users.
- Event counts are not necessarily sessions, orders or people. `event_value_usd` is the sum of the source event-value field across grouped events, not necessarily purchase revenue.
- No ad-platform API credentials or client data are used.
- This is an educational portfolio project, not a claim of professional media buying or activation experience.
